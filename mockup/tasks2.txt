# Kiro Task: Integrate ONLYOFFICE Docs Community Edition into Mentora

## Project

Mentora is an existing Laravel + React web application.

Current architecture:

- Backend: Laravel
- Frontend: React + Vite
- Database: MySQL/MariaDB
- Authentication: Laravel Sanctum
- Deployment/development: Docker
- Document formats required:
  - DOCX for Lesson Plans
  - XLSX for Class Records

ONLYOFFICE Docs Community Edition has ALREADY been installed and is currently running in Docker.

ONLYOFFICE URL during local development:

http://localhost:8080

The ONLYOFFICE health check currently returns HTTP 200 with:

true

Therefore:

IMPORTANT:
- DO NOT reinstall ONLYOFFICE.
- DO NOT create another ONLYOFFICE container.
- DO NOT replace the existing Docker configuration unless necessary.
- Inspect the existing project before making changes.
- Integrate ONLYOFFICE into the existing Mentora architecture.

Official documentation:

ONLYOFFICE React:
https://api.onlyoffice.com/docs/docs-api/get-started/frontend-frameworks/react/

https://helpcenter.onlyoffice.com/docs/installation/docs-community-install-docker.aspx

# PHASE 6 — DOCUMENT AUTHORIZATION

This is a school system containing academic records.

NEVER allow users to access arbitrary documents by changing:

/documents/{id}

Implement authorization.

For example:

User A owns document 123.

User B attempts:

GET /api/documents/123/editor

User B must receive:

403 Forbidden

unless the application's authorization rules explicitly allow access.

Reuse existing Laravel Policies/Gates if available.

Do not create a second authorization system if one already exists.

---

# PHASE 7 — DOCUMENT CONTENT ENDPOINT

ONLYOFFICE must be able to retrieve the actual document.

Implement:

GET /api/documents/{document}/content

The endpoint should:

1. Verify the document exists.
2. Verify access/authorization.
3. Retrieve the file from Laravel storage.
4. Return the correct MIME type.
5. Return the actual DOCX/XLSX content.

DOCX MIME type:

application/vnd.openxmlformats-officedocument.wordprocessingml.document

XLSX MIME type:

application/vnd.openxmlformats-officedocument.spreadsheetml.sheet

Do not expose the entire Laravel storage directory publicly.

Do not create unrestricted file download routes.

---

# PHASE 8 — ONLYOFFICE CALLBACK

Implement the ONLYOFFICE callback endpoint:

POST /api/documents/onlyoffice/callback

The callback must:

1. Receive the ONLYOFFICE callback.
2. Validate the request according to the current ONLYOFFICE JWT configuration.
3. Determine which Mentora document is being updated.
4. Correctly interpret ONLYOFFICE callback statuses.
5. When the document is ready to be saved, retrieve the updated document from the URL supplied by ONLYOFFICE.
6. Save the updated file to Laravel storage.
7. Update the document metadata/version.
8. Return the response expected by ONLYOFFICE.

Do NOT blindly save every callback.

Use the official ONLYOFFICE callback documentation.

Add logging for callback failures.

DO NOT log:
- student grades
- student names
- document contents
- JWT secrets
- sensitive academic data

---

# PHASE 9 — DOCUMENT KEY / VERSIONING

ONLYOFFICE requires a document key.

Do NOT generate a completely random key every time the editor loads.

The key should identify a particular document version.

For example, conceptually:

document-{id}-{version}

or:

document-{id}-{updated_at_timestamp}

Use an approach compatible with the existing database structure.

When a document is successfully updated:

- update its version/update timestamp
- generate a new document key for the next editing session

Avoid stale document sessions overwriting newer documents where practical.
